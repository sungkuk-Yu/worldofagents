## 1. 조이스틱 마이크 버튼 — 전체 제스처 매핑

### 1.1 기본 구조

조이스틱 마이크 버튼은 화면 7(음성 우선 홈)의 중앙에 위치하며, **탭·프레스·드래그** 3종 입력을 모두 받는다.
버튼 지름은 화면 너비의 22% (최소 80px, 최대 140px).

```
               [위: ↑]
              ↗       ↖
         [↖]    (●)    [↗]
              ↙       ↘
               [아래: ↓]

          ←  예      아니오  →

    ※ 중앙(●) = 마이크 버튼本体
```

### 1.2 8방향 + 중심 제스처 매핑 테이블

| 방향 | 코드 | 기본 동작 | 커스텀 가능 | 설명 |
|------|------|----------|------------|------|
| **중앙 탭** | `TAP_CENTER` | 녹음 시작/종료 | ❌ 고정 | 한 번 탭: 녹음 시작, 다시 탭: 녹음 종료 후 전송 |
| **중앙 롱프레스** | `LONG_CENTER` | 푸시투톡 (누르는 동안 녹음) | ❌ 고정 | 손가락을 떼면 자동 전송. 0.5초 이상 유지 시 활성화 |
| **좌 (←)** | `DIR_LEFT` | ✅ 예 (Yes) | ❌ 고정 | 큐 에이뉴런 질문 응답. 기본 내장 슬롯 |
| **우 (→)** | `DIR_RIGHT` | ❌ 아니오 (No) | ❌ 고정 | 큐 에이뉴런 질문 응답. 기본 내장 슬롯 |
| **상 (↑)** | `DIR_UP` | (미할당) | ✅ 커스텀 | 예: "파일 첨부", "최근 결과 다시 보기" |
| **하 (↓)** | `DIR_DOWN` | 현재 작업 취소 | ✅ 커스텀 (기본값=취소) | 진행 중 작업 중단. 확인 다이얼로그 없이 즉시 취소 |
| **좌상 (↖)** | `DIR_UPLEFT` | (미할당) | ✅ 커스텀 | 사용자 정의 슬롯 |
| **우상 (↗)** | `DIR_UPRIGHT` | (미할당) | ✅ 커스텀 | 사용자 정의 슬롯 |
| **좌하 (↙)** | `DIR_DOWNLEFT` | (미할당) | ✅ 커스텀 | 사용자 정의 슬롯 |
| **우하 (↘)** | `DIR_DOWNRIGHT` | (미할당) | ✅ 커스텀 | 사용자 정의 슬롯 |

### 1.3 제스처 인식 파라미터

```typescript
interface JoystickConfig {
  // 방향 인식
  deadzone: 12;           // px — 중심에서 이 거리 이내는 방향 없음으로 처리
  directionThreshold: 30; // px — 이 거리 이상 드래그해야 방향으로 인식
  angleSnap: 22.5;        // deg — 8방향 스냅 각도 (±22.5° 이내 = 해당 방향)

  // 시간 인식
  longPressDuration: 500; // ms — 이 이상 유지 시 롱프레스
  tapMaxDuration: 200;    // ms — 이 이하 = 탭
  
  // 피드백
  hapticOnDirection: true;     // 방향 감지 시 햅틱
  hapticOnRelease: true;       // 방향 확정 후 손가락 뗄 때 햅틱
  hapticPattern: 'light';      // 'light' | 'medium' | 'heavy'
}
```

### 1.4 조이스틱 상태별 시각 피드백

```
[평상시]              [터치 시작]            [방향 드래그 중]        [방향 확정]
                     
   ┌───┐               ┌───┐                ┌───┐                ┌───┐
   │ 🎤│    →         │ 🎤│    →          │ 🎤│ ←──   →       │ ✅│ ←──
   └───┘              └───┘               └───┘                └───┘
  펄스링 활성화       배경 약간 밝아짐      방향 인디케이터 표시   아이콘 변경 + 햅틱
  (아이들 상태)       (프레스 감지)         (화살표 + 라벨)       (실행 직전 확인)
```

- **아이들(idle):** 버튼 주변에 느린 펄스링(에이전트 색상, 2초 주기)
- **터치 시작:** 버튼 스케일 1.05x, 배경 밝기 +10%
- **드래그 중:** 드래그 방향에 반투명 화살표 + 방향 라벨(예: "예", "아니오", 또는 커스텀 라벨)
- **방향 확정(스냅):** 화살표 불투명 전환 + 해당 아이콘으로 변경 + 짧은 햅틱
- **릴리즈:** 액션 실행 + 버튼 원래 위치로 복귀 (스프링 애니메이션, 200ms)

### 1.5 롱프레스(푸시투톡) 상세 동작

```
시간 →
0ms        500ms                    N초                   릴리즈
│           │                        │                      │
├──탭 판별──┤──── 녹음 진행 ─────────┤──── 계속 녹음 ───────┤
│           │  🔴 녹음 인디케이터     │  트랜스크립트 실시간  │  ← 자동 전송
│           │  파형 애니메이션        │  표시                 │
```

- **0~500ms:** 탭 vs 롱프레스 판별 구간
- **500ms 경과:** 롱프레스 확정 → 🔴 녹음 표시 + 파형 애니메이션 시작
- **녹음 중:** 실시간 트랜스크립트가 버튼 아래에 표시
- **손가락 릴리즈:** 녹음 종료 → 자동 전송 (WebSocket `{"type":"commit"}` 프레임)
- **10초 초과:** 자동 종료 + "길이가 길어 자동으로 전송했어요" 토스트

### 1.6 좌/우(예/아니오) 응답 상세 흐름

큐 에이뉴런이 질문을 던졌을 때의 전체 인터랙션:

```
┌─────────────────────────────────────────┐
│                                         │
│     ┌───────────────────────────┐       │
│     │ 큐 에이뉴런 질문           │       │
│     │ "바쁘시면 이거 먼저        │       │
│     │  처리해드릴까요?"          │       │
│     └───────────────────────────┘       │
│                                         │
│          [예]     (●)     [아니오]      │
│           ←        🎤       →           │
│                                         │
│     ← 왼쪽으로 밀기     오른쪽으로 밀기 → │
│                                         │
└─────────────────────────────────────────┘
```

**사용자 응답 후 스레드 묶음 결과:**

```
┌─────────────────────────────────────────┐
│  Q: "바쁘시면 이거 먼저 처리해드릴까요?" │
│  A: ✅ 예                               │
│  R: "네, 먼저 처리하겠습니다!"           │
└─────────────────────────────────────────┘
  ↑ 질문→응답→후속반응 3단 카드 (영구 고정)
```

- 조이스틱 좌/우 드래그 시 해당 방향으로 카드가 살짝 밀려나는 애니메이션 (150ms)
- 응답이 확정되면 버튼 중앙으로 복귀 + 해당 응답 하이라이트 (0.5초)
- 3단 카드가 즉시 인라인에 삽입됨

```
│  │     │                                 │
│  │ ←  │  ●  │ →                         │
│  │ 예  │ 🎤  │ 아니오                    │
```

**커스텀 액션 유형:**

| 액션 유형 | 설명 | 아이콘 예시 |

| `CUSTOM_PROMPT` | 사용자 정의 프롬프트 실행 | 💬 |

### 2.4 결과 카드 → 카드 스레드 전환 애니메이션

```
Phase 1 (0ms)         Phase 2 (150ms)       Phase 3 (300ms)
┌──────────────┐     ┌──────────────┐     ┌──────────────┐
│              │     │──────────────│     │──────────────│
│   풀스크린    │     │ 축소 카드 고정 │     │ 축소 카드 고정 │

│              │     │              │     │              │
└──────────────┘     └──────────────┘     └──────────────┘
```

- Phase 1→2: 카드가 상단으로 스케일 다운 (1.0 → 0.3, 150ms, ease-out)
- Phase 2→3: 상단 고정 바에 흡착 + 하단에서 스레드 콘텐츠 슬라이드업 (150ms)

## 3. 공통 제스처 정의 (스와이프/탭/롱프레스)

### 3.1 제스처 인식 전역 설정

```typescript
interface GestureConfig {
  swipe: {
    minDistance: 50;        // px — 최소 스와이프 거리
    maxDuration: 300;       // ms — 최대 스와이프 소요 시간
    velocityThreshold: 0.5; // px/ms — 최소 스와이프 속도
  };
  longPress: {
    duration: 500;          // ms
    maxMovement: 10;        // px — 이 이상 움직이면 롱프레스 취소
  };
  doubleTap: {
    maxInterval: 250;       // ms — 두 탭 간 최대 간격
  };
}
```

### 3.2 화면별 제스처 맵

#### 화면 6 — 에이전트 선택 (캐러셀)

| 제스처 | 동작 | 애니메이션 |
|--------|------|-----------|
| 좌/우 스와이프 | 에이전트 카드 전환 | 현재 카드 축소+흐림, 다음 카드 확대+선명 (300ms 스프링) |
| 탭 | 활성 에이전트 선택 → 화면 7 진입 | 카드가 화면 중앙으로 확대 전환 (250ms) |
| 롱프레스 | 에이전트 카드 컨텍스트 메뉴 (설정/삭제/명함) | 바텀시트 메뉴 슬라이드업 |
| 더블탭 | 즉시 해당 에이전트 홈 진입 | 탭과 동일하되 확인 단계 건너뜀 |
| 핀치-인 | 캐러셀 → 그리드 뷰 전환 | 카드 축소 + 그리드 레이아웃 페이드인 |

**단계별 문구 (순차 전환):**

| 단계 | 상태 텍스트 | 소요 시간(예상) | 캐릭터 말투 예시 |
|------|-----------|---------------|----------------|
| 1 | 💭 떠오리는 중... | 0~1초 | "잠깐만요, 기억 뒤지고 있어요" |
| 2 | 🧠 생각하는 중... | 1~3초 | "흠... 이건 좀 고민되네요" |
| 3 | ✏️ 정리하는 중... | 3~5초 | "거의 다 됐어요, 조금만요" |
| 4 | 📦 곧 보내드릴게요 | 5초+ | "기다리게 해서 미안해요!" |

- 각 단계 전환 시 부드러운 페이드 전환 (200ms)
- 캐릭터 말투는 문구뱅크에서 무작위 추출, 동일 세션 내 중복 방지
- **실시간 트랜스크립트**: 답변생성 에이뉴런이 텍스트 생성 중이면 하단에 스트리밍 표시

```typescript

```

```
↑ → ↗ → → → ↘ → ↓ → ↙ → ← → ↖ → (루프)
```

#### D. 라이브 리전 (실시간 업데이트 알림)

| 영역 | live 속성 | 설명 |
|------|----------|------|

### 6.4 색상 접근성

- 모든 상태 색상은 WCAG 2.1 AA 기준 대비 4.5:1 이상 유지
- 에러/성공 상태를 색상만으로 구분하지 않음 — 반드시 아이콘 + 텍스트 병기
- 다크 모드 기본, 라이트 모드 선택
- 색각이상 대응: 상태 표시에 패턴/아이콘 중복 사용

```
에러 상태:    ⚠️ + 주황색 + "응답을 가져오지 못했어요"
성공 상태:   ✅ + 녹색 + "완료되었습니다"
로딩 상태:   💭 + 펄스 + "생각하는 중..."
오프라인:    📡 + 노란 배너 + "오프라인"
```

## 7. 왼손잡이 모드 상세

### 7.1 기본 원칙

왼손잡이 모드(화면 5 설정)는 **화면 레이아웃의 좌우를 반전**시키되, **콘텐츠 자체는 미러링하지 않는다.**

```
[오른손잡이 기본]           [왼손잡이 모드]
┌──────────────────┐    ┌──────────────────┐
│      설정 ⚙      │    │      설정 ⚙      │
│                  │    │                  │
│                  │    │                  │
│     (●) 🎤      │    │     (●) 🎤      │
│                  │    │                  │
│  ← 예   아니오 → │    │ ← 아니오   예 →  │  ← 조이스틱 좌우 반전
│  [📎]     [📷]  │    │  [📷]     [📎]  │  ← 액션 버튼 좌우 반전
└──────────────────┘    └──────────────────┘
```

### 7.2 반전 대상 / 비반전 대상

| 요소 | 반전 여부 | 이유 |
|------|----------|------|
| 조이스틱 좌/우 매핑 (예/아니오) | ✅ 반전 | 왼손으로 밀기 편한 방향으로 변경 |
| 하단 액션바 버튼 배치 | ✅ 반전 | 첨부/카메라 등 버튼 위치 좌우 교체 |
| 스와이프 방향 (이전/다음) | ✅ 반전 | 왼쪽 스와이프 = 다음, 오른쪽 = 이전 |
| 뒤로 스와이프 (iOS) | ❌ 유지 | OS 표준 제스처는 변경하지 않음 |
| 텍스트 정렬 | ❌ 유지 | LTR 언어는 좌측 정렬 유지 |
| 아바타/캐릭터 | ❌ 유지 | 미러링하면 부자연스러움 |
| 시계 방향 회전 애니메이션 | ❌ 유지 | 물리적 방향은 유지 |
| 뒤로가기 화살표 (←) | ❌ 유지 | 의미적 방향은 유지 |
| 세그먼트 진행바 | ❌ 유지 | 시간 흐름은 좌→우 유지 |
| 설정 화면 레이아웃 | ✅ 반전 | 토글/버튼 위치 반전 |
| 사이드바 (PC) | ✅ 반전 | 좌↔우 사이드바 위치 교환 |

### 7.3 조이스틱 매핑 반전 상세

```
[오른손잡이 기본]              [왼손잡이 모드]

       ↑ (커스텀)                    ↑ (커스텀)
      ↗   ↖                        ↗   ↖
  ← 예    아니오 →            ← 아니오    예 →
      ↙   ↘                        ↙   ↘
       ↓ (취소)                    ↓ (취소)
```

**코드 수준 매핑:**

```typescript
const joystickMapping = {

    LEFT:  'YES',
    RIGHT: 'NO',
  },
  leftHanded: {
    LEFT:  'NO',    // 반전
    RIGHT: 'YES',   // 반전
  },
  // 상하/대각선은 반전하지 않음
  common: {
    UP:    'CUSTOM_SLOT_1',
    DOWN:  'CANCEL',
    UPLEFT: 'CUSTOM_SLOT_2',
    // ...
  }
};
```

```typescript
interface LeftHandedConfig {

  // 키: user_settings.left_handed_mode
```

- 설정 변경 즉시 현재 화면에 반영 (애니메이션: 크로스페이드 200ms)
- 다른 기기 로그인 시에도 설정 동기화 (관계 기반 세션 라우팅, 백서 4.0절)

## 부록 A — 제스처 충돌 해결 규칙

여러 제스처가 동시에 감지될 때 우선순위:

```
우선순위 (높음 → 낮음):

1. 시스템 제스처 (뒤로가기, 홈 등)
2. 조이스틱 방향 드래그 (방향 임계값 초과 시)
3. 롱프레스 (시간 임계값 초과 시)
4. 스와이프 (거리+속도 임계값 초과 시)
5. 더블탭
6. 싱글 탭
```

**충돌 시나리오별 해결:**

| 시나리오 | 해결 |
|----------|------|
| 스와이프 중 방향 임계값 초과 | 조이스틱 드래그로 전환 |
| 롱프레스 중 손가락 움직임 > 10px | 롱프레스 취소, 드래그로 전환 |
| 더블탭 감지 중 첫 탭 | 250ms 대기 후 싱글탭 확정 또는 더블탭 확정 |
| 결과 카드 스와이프 + OS 뒤로가기 | OS 제스처 우선 |
| 스크롤 중 수평 스와이프 | 주 축(수직/수평) 판별 후 해당 방향으로 락 |
