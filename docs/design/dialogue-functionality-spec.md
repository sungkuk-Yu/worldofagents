## 1. 개요 및 설계 원칙

### 1.1 이 문서의 목적

기존 기획서(`agenttalk-modern-ux-plan.md` 3장)에서 선언한 "다이얼로그 기능성 = 대화 목적별 특화 컴포넌트" 개념을 **실제 구현 가능한 수준**으로 심화한다. 백서의 핵심 원칙 세 가지를 기능성 설계의 제약조건으로 삼는다:

| 원칙 | 백서 출처 | 기능성 제약 |
|------|----------|------------|
| 채팅버블 탈피 → 기능 중심 대화 | 백서 3.8절 | 모든 컴포넌트는 좌우 말풍선이 아닌 풀스크린/카드 형태로 렌더링 |
| 대화 목적별 특화 컴포넌트 | 기획서 1.3절 | 단일 범용 UI가 아닌 유형별 전용 컴포넌트 제공 |
| 동적 전환 (정보→데이터→파일) | 기획서 3.2절 | 컴포넌트 간 전환은 매끄럽고 사용자 의도에 반응적 |

### 1.2 핵심 설계 제약

1. **사용자는 대화 유형을 "선택"하지 않는다** — 사용자가 "이건 데이터 조작형이야"라고 선언하는 게 아니라, 시스템이 자동 판별하거나 사용자가 자연스럽게 유도한다.
2. **전환은 되돌릴 수 있다** — 정보→데이터로 전환 후 다시 정보로 돌아갈 수 있어야 하며, 이전 상태가 보존된다.
3. **에이뉴런 구조와 연동** — 각 컴포넌트의 렌더링/생성은 비주얼 에이뉴런·답변생성 에이뉴런과 연결된다 (백서 3.3절).
4. **결과 중심 렌더링 유지** — 어떤 컴포넌트로 전환하든 화면 10(결과 캔버스)의 풀스크린 원칙을 유지한다.

## 2. 대화 유형 자동 판별 방식

### 2.1 판별 방식 3종 비교

| 방식 | 장점 | 단점 | 적합 상황 |
|------|------|------|----------|
| **LLM 의도 분류** | 자연어 유연성, 맥락 이해 | 지연시간 200~800ms, 비용, 오판 시 복구 비용 | 복잡하거나 모호한 요청 |
| **키워드/패턴 매칭** | 즉각적 반응(0ms), 비용 0 | 유연성 낮음, 다국어 대응 어려움 | 명확한 트리거가 있는 요청 |
| **사용자 명시(수동 전환)** | 오판 0%, 사용자 통제감 | 매번 선택 부담, 미니멀 UX 저해 | 판별 실패 시 폴백, 고급 사용자 |

### 2.2 3단계 하이브리드 판별 (권장안)

```
┌──────────────────────────────────────────────────┐
│                 사용자 입력 수신                    │
└──────────────────┬───────────────────────────────┘
                   │
        ┌──────────▼──────────┐
        │  Stage 1: 패턴 매칭   │  ← 즉각 판별 (0ms)
        │  (키워드 + 구조 분석)  │
        └──────────┬──────────┘
                   │
            ┌──────▼──────┐
            │  매칭 성공?   │
            └──┬───────┬──┘
          Yes  │       │  No
               │       │
    ┌──────────▼──┐   ┌▼─────────────────────┐
    │ 즉시 컴포넌트 │   │  Stage 2: LLM 분류    │  ← 공감 에이뉴런 응답 후
    │ 전환 결정    │   │  (비동기, 200~800ms)  │     백그라운드 실행
    └─────────────┘   └──────────┬───────────┘
                                 │
                          ┌──────▼──────┐
                          │ 신뢰도 ≥ 0.8?│
                          └──┬───────┬──┘
                        Yes  │       │  No
                             │       │
                  ┌──────────▼──┐   ┌▼───────────────┐
                  │ 컴포넌트 전환 │   │  Stage 3:       │
                  │ (자동)       │   │  사용자 확인    │
                  └─────────────┘   └────────────────┘
```

### 2.3 Stage 1 — 키워드/패턴 매칭 규칙

즉시 판별이 가능한 고신뢰 패턴을 미리 정의한다. 오탐률을 극단적으로 낮게 잡는 것이 핵심 — 매칭 안 되면 Stage 2로 넘길 뿐이므로, **놓치는 것보다 오판이 훨씬 위험하다.**

```yaml
# 대화 유형 패턴 매칭 규칙 (예시)
patterns:
  data_manipulation:
    keywords: ["표로", "차트로", "엑셀", "스프레드시트", "정리해줘", "비교표",
               "통계", "평균", "합계", "정렬", "필터", "피벗"]
    structure_patterns:
      - "\\d+개.*(?:비교|정리|목록)"    # "5개 비교해줘"
      - "(?:표|차트|그래프).*(?:만들어|그려|작성)"
    confidence: 0.95

  file_processing:
    triggers:
      - file_attachment_detected        # 파일 첨부 감지 시 자동
    keywords: ["이 파일", "첨부한", "PDF", "문서", "분석해줘",
               "요약해줘", "번역해줘", "이 이미지"]
    confidence: 0.95

  task_delegation:
    keywords: ["해줘", "예약해", "발송해", "보내줘", "주문해",
               "알림설정", "일정잡아", "전화해줘"]
    structure_patterns:
      - ".+(?:해줘|해주세요|부탁해)"
    confidence: 0.85   # "해줘"는 정보 요청에도 쓰이므로 낮게

  information_response:
    # 기본 폴백 — 다른 패턴에 매칭되지 않으면 정보 응답형
    default: true
    confidence: 0.5    # LLM 확인 필요
```

**패턴 매칭 우선순위:** 파일 첨부 감지 > 데이터 조작 > 작업 위임 > 정보 응답(폴백)

**다국어 대응:** 키워드 목록은 `i18n/patterns/{locale}.yaml`로 관리. 초기 지원 언어: 한국어, 영어, 일본어 (백서 4.4절 글로벌 클러스터와 동기화).

### 2.4 Stage 2 — LLM 의도 분류

공감 에이뉴런이 먼저 응답("확인해볼게요~")하는 동안, 백그라운드에서 LLM이 의도를 분류한다.

**LLM 분류 프롬프트 구조:**

```
System: 당신은 사용자 요청의 대화 유형을 분류합니다.
아래 5개 유형 중 하나를 선택하고, 신뢰도를 0.0~1.0으로 반환하세요.

유형:
- information: 정보 조회, 질문, 검색 (결과 카드로 응답)
- data: 데이터 분석, 표/차트 작성, 비교 정리 (스프레드시트로 응답)
- file: 파일 열람, 분석, 변환, 요약 (파일 뷰어로 응답)
- task: 실제 행동 위임 — 발송, 예약, 주문, 실행 (작업 플로우로 응답)
- multi_agent: 여러 에이전트 참여 필요 (에이전트 협업 뷰로 응답)

반드시 아래 JSON 형식으로만 응답하세요:
{"type": "<유형>", "confidence": <0.0~1.0>, "reason": "<한 줄 근거>"}

User: {사용자 입력 + 최근 대화 컨텍스트 3턴}
```

**모델 선택:** 분류용으로는 소형·저지연 모델 사용 (GPT-4o-mini / Claude Haiku급). 분류와 답변 생성은 별도 모델로 분리해 비용·속도 최적화.

**컨텍스트 포함 범위:** 최근 3턴 + 현재 활성 컴포넌트 유형. "이거 표로 바꿔줘"에서 "이거"가 무엇을 가리키는지 직전 컴포넌트로 판단.

### 2.5 Stage 3 — 사용자 확인 (폴백)

LLM 신뢰도가 0.8 미만일 때, 또는 판별 결과가 직전 대화 맥락과 충돌할 때 사용자에게 확인한다.

**확인 UX (조이스틱 연동):**
```
┌─────────────────────────────────────┐
│                                     │
│  "이 요청을 어떻게 처리할까요?"       │
│                                     │
│  [📊 표로 정리]  [📄 문서로 보기]     │
│                                     │
│  또는 조이스틱 ← → 로 선택          │
│                                     │
└─────────────────────────────────────┘
```

- 버튼 탭 또는 조이스틱 좌우로 선택
- 3초 내 응답 없으면 LLM 최고 신뢰도 유형으로 자동 진행 (하단에 "다른 형식으로 보시려면 말씀해주세요" 안내)
- 사용자의 선택은 학습 데이터로 누적 → 해당 사용자의 패턴 매칭 가중치 조정

### 2.6 판별 결과의 에이뉴런 연동

| 판별 유형 | 활성 에이뉴런 | 역할 |
|----------|--------------|------|
| 정보 응답 | 공감 + 답변생성 | 텍스트 응답 생성 → 결과 카드 렌더링 |
| 데이터 조작 | 공감 + 답변생성 + 비주얼 | 답변생성이 데이터 구조 결정 → 비주얼이 표/차트 렌더링 |
| 파일 처리 | 공감 + 답변생성 + 비주얼 | 답변생성이 파일 분석 → 비주얼이 분석 결과 시각화 |
| 작업 위임 | 공감 + 답변생성 + 큐 | 답변생성이 작업 계획 → 큐가 진행상태 추적 |
| 멀티 에이전트 | 공감 + 답변생성 + 큐 | 오케스트레이터가 외부 에이전트 연결 관리 |

**조기 위임 원칙 (백서 3.3절):** 판별 결과 표·차트가 필요하다고 판단된 순간, 답변 전체가 완성되길 기다리지 않고 즉시 비주얼 에이뉴런에게 작업을 위임한다.

## 3. 컴포넌트별 구체적 기능 목록

### 3.1 정보 응답형 (Information Response)

**활용 장면:** 날씨, 주가, 검색 결과, 뉴스, 간단 Q&A, 번역, 정의

#### 기본 기능

| 기능 | 설명 | MVP |
|------|------|-----|
| 풀스크린 카드 | 결과를 화면 전체에 카드 형태로 렌더링 (화면 10) | ✅ |
| 후속 질문 오버레이 | 카드 하단에 마이크 버튼, 음성/텍스트로 후속 질문 | ✅ |
| 공유 | 카드를 이미지/텍스트로 공유 (시스템 공유시트) | ✅ |
| 저장/즐겨찾기 | 카드를 즐겨찾기에 추가 (화면 12 연동) | ✅ |
| 카드 스와이프 | 관련 카드를 좌우로 스와이프 (여러 검색 결과) | Phase 2 |

#### 특화 카드 유형

| 카드 유형 | 포함 요소 | 렌더링 규칙 |
|----------|----------|------------|
| 날씨 카드 | 현재 기온, 시간별/요일별 예보, 강수 확률 | 3단 세로 레이아웃 |
| 주가/환율 | 현재가, 변동률, 미니 차트(스파크라인) | 실시간 업데이트 배지 |
| 검색 결과 | 제목, 요약, 출처 링크, 신뢰도 표시 | 최대 5개, 더보기 스크롤 |
| 번역 | 원문 + 번역문 병렬, 언어 자동 감지 | 좌우 분할(가로 모드), 상하(세로 모드) |
| 정의/사전 | 용어, 정의, 관련 용어 링크 | 위키스타일 카드 |
| 뉴스 | 헤드라인, 출처, 발행시간, 관련 뉴스 | 시간순 정렬 |

#### 정보 신뢰도 표시 (백서 4.1-4항 연동)
- **교차검증 배지:** 여러 모델이 동의한 결과 → ✅ 초록 배지
- **단일 모델 결과:** ⚠️ 노란 배지 + "추가 확인 권장"
- **출처 링크:** 클릭 시 원본 페이지 프리뷰 (인앱 브라우저)

### 3.2 데이터 조작형 (Data Manipulation)

**활용 장면:** 표 작성, 데이터 비교, 통계 분석, 차트 생성, 리스트 정리

#### 기본 기능 (백서 3.7절 "노션이 아니라 엑셀" 원칙 준수)

| 기능 | 설명 | MVP |
|------|------|-----|
| 스프레드시트 뷰 | 셀 기반 표 렌더링, 핀치줌 지원 | Phase 2 |
| 셀 편집 | 탭 → 편집, 값/서식 변경 | Phase 2 |
| 행/열 추가·삭제 | 롱프레스 → 삽입/삭제 메뉴 | Phase 2 |
| 정렬 | 열 헤더 탭 → 오름차순/내림차순 | Phase 2 |
| 필터 | 열 헤더 롱프레스 → 필터 조건 설정 | Phase 2 |
| 기본 수식 | SUM, AVG, COUNT, MAX, MIN 자동 인식 | Phase 2 |
| 차트 변환 | 표 선택 → "차트로 보기" 버튼 → 막대/선/원형 | Phase 2 |
| 전체화면 확대 | 표 탭 → PDF 뷰어처럼 전체화면 확대 | ✅ |
| 음성으로 수정 | "3행 매출 500만으로 바꿔줘" → 해당 셀 업데이트 | Phase 2 |
| PDF/CSV 내보내기 | 공유 메뉴에서 형식 선택 | Phase 2 |
| 실행 취소/다시 실행 | 상단 툴바에 undo/redo | Phase 2 |

#### 셀 서식 지원 범위

```
- 텍스트: 굵기, 기울임, 색상, 배경색
- 숫자: 소수점 자리수, 천 단위 구분, 통화 기호
- 날짜: yyyy-mm-dd, yyyy년 mm월 dd일, 상대 날짜(D+7)
- 조건부 서식: 값 범위에 따른 셀 색상 자동 변경
- 병합: 인접 셀 선택 → 병합
```

#### AI 보조 기능

| 기능 | 동작 |
|------|------|
| 자동 헤더 추론 | 데이터 패턴에서 열 제목 자동 제안 |
| 결측치 표시 | 빈 셀을 회색으로 표시, "채우기" 옵션 제공 |
| 이상치 하이라이트 | 통계적 이상치 자동 감지, 노란 테두리 표시 |
| 자연어 수식 | "매출의 10% 계산해줘" → 해당 열에 수식 삽입 |
| 표 요약 | 표 하단에 핵심 인사이트 한 줄 자동 생성 |

### 3.3 파일 처리형 (File Processing)

**활용 장면:** 문서 분석, 이미지 인식, PDF 요약, 코드 리뷰, 오디오/비디오 요약

#### 기본 기능

| 기능 | 설명 | MVP |
|------|------|-----|
| 파일 프리뷰 | 파일 형식별 네이티브 렌더링 (PDF, 이미지, 오피스) | ✅ |
| AI 분석 패널 | 파일 내용 기반 요약, 핵심 포인트 추출 | ✅ |
| 하이라이트 | 중요 구문 자동 강조 + 수동 하이라이트 추가 | Phase 2 |
| Q&A 스레드 | 파일에 대한 질문 → 해당 위치 참조와 함께 답변 | Phase 2 |
| 페이지/구간 지정 | "3페이지 요약해줘", "2:30~4:00 뭐라고 해?" | Phase 2 |
| 파일 간 비교 | 2개 파일 동시 열기 → 차이점 비교 패널 | Phase 3 |
| 변환 | PDF→텍스트, 이미지→텍스트(OCR), 오디오→텍스트(STT) | Phase 2 |
| 메타데이터 표시 | 파일 크기, 생성일, 형식, 페이지 수 상단 표시 | ✅ |

#### 파일 형식별 특화 처리

| 형식 | 렌더링 | AI 분석 |
|------|--------|---------|
| PDF | 페이지 단위 스크롤, 핀치줌 | 페이지별 요약, 목차 추출, 키워드 하이라이트 |
| 이미지 (JPG/PNG) | 라이트박스 확대, 제스처 줌 | OCR, 객체 인식, 색상 팔레트 추출 |
| Word/Docs | 원본 서식 유지 프리뷰 | 단락별 요약, 변경 제안 |
| Excel/Sheets | 3.2 데이터 조작형으로 자동 전환 | 시트별 구조 분석 |
| 오디오 (MP3/WAV) | 파형 시각화 + 재생 컨트롤 | STT → 전문 + 요약 + 화자 분리 |
| 비디오 (MP4) | 썸네일 + 재생 컨트롤 + 자막 | 장면 분리, 자막 추출, 핵심 장면 요약 |
| 코드 (.py/.js 등) | 구문 강조 + 줄 번호 | 코드 리뷰, 버그 감지, 리팩토링 제안 |
| ZIP/압축 | 파일 목록 트리 뷰 | 내용물 요약, 특정 파일 추출 |

#### 파일 처리 플로우

```
파일 첨부 감지
    │
    ├── 이미지 → OCR/객체분석 → 결과 카드
    ├── PDF → 전문 추출 → 요약 + 목차 카드
    ├── Excel/CSV → 자동 데이터 조작형 전환
    ├── 오디오 → STT → 전문 + 요약 카드
    ├── 비디오 → 자막 추출 + 장면 분석 → 타임라인 카드
    └── 기타 → 파일 정보 카드 + "무엇을 할까요?" 옵션
```

### 3.4 작업 위임형 (Task Delegation)

**활용 장면:** 메시지 발송, 예약, 주문, 알림 설정, 일정 관리, 반복 작업

#### 기본 기능 (백서 3.9절 연동)

| 기능 | 설명 | MVP |
|------|------|-----|
| 작업 계획 카드 | 수행할 작업을 단계별로 표시, 확인 요청 | ✅ |
| 진행 상태 추적 | 시작 → 진행중 → 완료/막힘 4단계 상태 | ✅ |
| 실시간 상태 업데이트 | 작업 진행 상황을 스트리밍으로 표시 | ✅ |
| 수정 버튼 | 진행 중인 작업의 방향 전환/추가 지시 | Phase 2 |
| 즉시 중단 버튼 | 백엔드 프로세스 즉시 정지 (SIGTERM) | ✅ |
| 완료 확인 | 작업 완료 시 결과 카드 + 확인 요청 | ✅ |
| 반복 작업 설정 | "매주 월요일마다 이거 해줘" → 스케줄 등록 | Phase 3 |

#### 작업 상태 모델

```typescript
type TaskStatus = 
  | 'planned'      // 계획 수립, 사용자 확인 대기
  | 'confirmed'    // 사용자 승인, 실행 대기
  | 'in_progress'  // 실행 중
  | 'waiting'      // 외부 응답 대기 (API, 상대방)
  | 'completed'    // 성공 완료
  | 'failed'       // 실패 (원인 포함)
  | 'cancelled'    // 사용자 중단
  | 'blocked';     // 막힘 (해결 필요)

interface Task {
  id: string;
  title: string;
  status: TaskStatus;
  steps: TaskStep[];
  createdAt: Date;
  updatedAt: Date;
  estimatedDuration?: string;  // "약 3분"
  approvalRequired: boolean;   // 민감한 행동 여부
  result?: ResultCard;         // 완료 시 결과
}
```

#### 승인 게이트 (백서 3.3절)

| 행동 민감도 | 예시 | 승인 필요 |
|------------|------|----------|
| **높음** | 결제, 개인정보 공유, 메시지 발송, 삭제 | ✅ 반드시 사용자 승인 |
| **중간** | 예약 확정, 파일 변환, 외부 API 호출 | ✅ 기본 승인, 설정으로 스킵 가능 |
| **낮음** | 정보 검색, 파일 읽기, 초안 작성 | ❌ 자율 처리 |

**승인 UX:** 작업 계획 카드 하단에 [실행하기] [수정하기] 버튼. 조이스틱 →(예) = 실행, ←(아니오) = 수정/취소.

#### 작업 유형별 특화

| 작업 유형 | 특화 컴포넌트 | 추가 기능 |
|----------|--------------|----------|
| 메시지 발송 | 수신자 확인 + 내용 미리보기 | 발송 전 편집, 발송 취소(5초 내) |
| 일정/예약 | 캘린더 미니 뷰 + 시간 슬롯 | 충돌 감지, 대체 시간 제안 |
| 주문/결제 | 상품 카드 + 금액 확인 | 결제 수단 선택, 영수증 |
| 파일 변환 | 변환 전/후 프리뷰 | 품질 설정, 형식 선택 |
| 알림/리마인더 | 시간 선택 + 반복 설정 | 지오펜스 트리거, 조건부 알림 |

**활용 장면:** 여러 에이전트가 참여하는 회의, 분업적 작업, 에이전트 간 협상

```
┌────────────────────────────────────────────────┐
│               협업 모드 선택                      │

│                                                │

│  🎯 위임 모드 (Delegated)                       │

│                                                │

```

|------|------|

| 중단 프로토콜 | 사용자가 중단 시 진행 중인 모든 작업 즉시 정지 + 상태 저장 |

## 4. 컴포넌트 간 전환 UX 플로우

### 4.1 전환 원칙

1. **전환은 매끄럽다** — 화면이 깜빡이거나 로딩 스크리너가 길게 뜨지 않는다.
2. **이전 상태 보존** — 전환 전 컴포넌트의 데이터/스크롤 위치가 유지된다.
3. **전환 시각적 피드백** — 컴포넌트가 변하는 것을 사용자가 인지할 수 있도록 짧은 트랜지션.
4. **되돌리기 가능** — "아까 그 표로 돌아가줘"로 이전 컴포넌트 복원.

### 4.2 전환 트리거 매트릭스

| 현재 → 전환 | 정보 응답 | 데이터 조작 | 파일 처리 | 작업 위임 | 멀티 에이전트 |
|------------|----------|-----------|---------|---------|-------------|
| **정보 응답** | — | "표로 정리해줘" | "이거 파일로 만들어줘" | "이 정보로 예약해줘" | "다른 에이전트도 불러와" |
| **데이터 조작** | "이 표 요약해줘" | — | "이 데이터 파일로 저장" | "이 데이터로 메일 보내줘" | "분석 에이전트 추가" |
| **파일 처리** | "이 파일 뭐야?" | "표를 엑셀로 열어줘" | — | "이 파일 인쇄해줘" | "번역 에이전트 연결" |
| **작업 위임** | "진행 상황 알려줘" | "결과를 표로 정리" | "결과 파일 받아" | — | "다른 에이전트에게 인계" |
| **멀티 에이전트** | "결과 요약해줘" | "결과를 표로" | "공유 파일 열기" | "다음 단계 진행" | — |

### 4.3 전환 애니메이션 상세

```
[정보 카드]
    │  사용자가 "이거 표로 정리해줘"
    │
    ▼ ① 공감 에이뉴런 즉시 응답: "표로 만들어볼게요~"
    │
    ▼ ② 현재 카드가 상단으로 슬라이드 + 축소 (0.3초)
    │    → "고정 참조 바"로 상단에 남음 (화면 11 카드 스레드 방식)
    │
    ▼ ③ 비주얼 에이뉴런이 스프레드시트 뷰 생성 (스트리밍)
    │    → 셀 단위로 순차 렌더링 (0.5~2초)
    │
    ▼ ④ 스프레드시트 뷰 풀스크린 표시
    │    → 상단에 원본 카드 축소 참조 바 유지
    │
    [스프레드시트 뷰]
```

### 4.4 전환 히스토리 (Compoment Stack)

전환된 컴포넌트는 스택으로 관리되어, 사용자가 자유롭게 오갈 수 있다.

```
┌────────────────────────────────────────────────┐
│  컴포넌트 히스토리 (상단 세그먼트 바)              │
│                                                │
│  [정보카드①] ──→ [표②] ──→ [파일③] ← 현재      │
│     ↑              ↑          ↑                │
│   탭하면          탭하면      현재              │
│   해당 상태로     해당 상태로                    │
│   복원            복원                           │
│                                                │
│  ← 스와이프: 이전 컴포넌트로                     │
│  → 스와이프: 다음 컴포넌트로                     │
└────────────────────────────────────────────────┘
```

**세그먼트 바 기능:**
- 화면 10의 "상단 얇은 진행바(세그먼트)"를 컴포넌트 히스토리로 활용
- 각 세그먼트 탭 → 해당 컴포넌트로 즉시 복원
- 세그먼트 롱프레스 → 해당 컴포넌트 삭제/닫기
- 10개 초과 시 가장 오래된 것부터 자동 보관 (즐겨찾기로 이동)

### 4.5 복합 전환 시나리오

**시나리오: 회식비 정산 요청**

```
사용자: "지난주 회식비 정산해줘"
  → [작업 위임] 정산 작업 계획 카드 표시
  → 사용자 승인 → 진행 중 상태

사용자: "영수증 사진 보낼게" (파일 첨부)
  → [파일 처리] 영수증 OCR → 금액 자동 추출
  → 자동으로 [작업 위임] 복원 + OCR 결과 반영

사용자: "사람별로 정리해줘"
  → [데이터 조작] 인원별 정산 표 표시
  → 상단에 작업 위임 상태 바 유지 ("정산 진행 중")

사용자: "이대로 카톡으로 보내줘"
  → [작업 위임] 발송 확인 카드 → 승인 → 완료
  → [정보 응답] 발송 완료 확인 카드
```

### 4.6 전환 실패 처리

| 상황 | 처리 |
|------|------|
| 변환 불가 (이미지에서 표 추출 실패) | "표로 변환하기 어려워요. 대신 이렇게 보여드릴게요" + 최선의 대안 표시 |
| 전환 중 오류 | 현재 컴포넌트 유지 + 에러 토스트 + "다시 시도할까요?" |
| 지원 불가 전환 (비디오→스프레드시트) | "비디오를 표로 정리하는 건 아직 지원하지 않아요" + 대안 제안 |

## 5. 기능성 우선순위 (MVP vs Phase2+)

### 5.1 우선순위 매트릭스

```
              높은 사용자 가치
                   │
    MVP (Phase 1)  │  Phase 2
    ───────────────┼───────────────
    정보 응답 카드   │  데이터 조작(표/차트)
    작업 위임 기본   │  파일 처리 심화
    결과 캔버스      │  카드 스레드
    후속 질문       │  컴포넌트 전환
                   │
    ───────────────┼───────────────
    멀티 에이전트    │  Phase 4+
    기본           │  고급 협업
                   │  IoT 연동
                   │  주문/결제 대행
    낮은 구현 난이도  │  높은 구현 난이도
```

### 5.2 Phase별 상세 범위

#### Phase 1 — MVP (핵심 대화 기능)

**목표:** "말을 걸면 처리된다"는 핵심 가치 증명

| 컴포넌트 | 포함 기능 | 제외 기능 |
|---------|----------|----------|
| 정보 응답 | 풀스크린 카드, 날씨/검색/Q&A, 공유, 저장 | 카드 스와이프, 교차검증 배지 |
| 작업 위임 | 작업 계획 확인, 진행 상태 4종, 즉시 중단 | 수정 버튼, 반복 작업 |
| 파일 처리 | 파일 프리뷰(PDF/이미지), 기본 요약 | 하이라이트, Q&A 스레드, 변환 |
| 판별 | Stage 1(키워드) + Stage 2(LLM) 기본 | Stage 3(사용자 확인), 학습 |

**성공 지표:**
- 정보 응답 카드 렌더링 ≤ 2초 (공감 응답 포함)
- 작업 위임 → 완료까지 사용자 추가 입력 0회 (단발 위임 기준)
- 대화 유형 판별 정확도 ≥ 85%

#### Phase 2 — 기능성 확장

**목표:** "채팅버블 탈피" 체감 완성

| 컴포넌트 | 신규 기능 |
|---------|----------|
| 데이터 조작 | 스프레드시트 뷰 전체 (셀 편집, 정렬, 필터, 차트) |
| 파일 처리 | 하이라이트, Q&A 스레드, OCR, STT, 변환 |
| 컴포넌트 전환 | 동적 전환 + 세그먼트 히스토리 바 |
| 판별 | Stage 3(사용자 확인), 사용자별 패턴 학습 |
| 작업 위임 | 수정 버튼, 완료 결과 카드 |
| 카드 스레드 | 화면 11 전체 (원본 고정 참조, 후속 대화) |

**성공 지표:**
- 컴포넌트 전환 후 사용자 재요청 없이 목적 달성률 ≥ 70%
- 스프레드시트 사용자 직접 편집 비율 ≥ 30% (음성 의존도 감소)
- 전환 실패율 ≤ 5%

#### Phase 3 — 멀티 에이전트

**목표:** "에이전트 간 소통" 차별화 실현

| 기능 | 상세 |
|------|------|
| 멀티 에이전트 대화방 | 통합/독립/위임 모드 |
| 에이전트 초대/퇴장 | QR/명함으로 대화 중 초대 |
| 에이전트 간 대화 열람 | RPC 로그 뷰어 |
| 개입/중단 프로토콜 | "잠깐만" 일시정지 + 재개 |
| 승인 게이트 | 민감도별 자동 분류 + 승인 UI |
| 파일 비교 | 2개 파일 동시 분석 |
| 반복 작업 | 스케줄 기반 자동 실행 |

#### Phase 4+ — 고급 기능

| 기능 | 전제 조건 |
|------|----------|
| 큐 에이뉴런 완전체 | 끼어들기 판별 + 실시간 병합 |
| 비주얼 에이뉴런 완전체 | 인포그래픽 자동 생성 + 스트리밍 |

| IoT 제어 | IoT 스킬 카테고리 성숙 시 |
| 주문/결제 대행 | 외부 API 파트너십 확보 시 |

### 6.1 프론트엔드 아키텍처

#### 컴포넌트 레지스트리 패턴

각 다이얼로그 컴포넌트를 레지스트리에 등록하고, 판별 결과에 따라 동적으로 마운트한다.

```typescript
// 다이얼로그 컴포넌트 레지스트리
const DialogRegistry = {
  information: lazy(() => import('./dialogs/InfoCard')),
  data: lazy(() => import('./dialogs/SpreadsheetView')),
  file: lazy(() => import('./dialogs/FileViewer')),
  task: lazy(() => import('./dialogs/TaskFlow')),
  multi_agent: lazy(() => import('./dialogs/MultiAgentView')),
};

// 컴포넌트 마운트
function DialogueRenderer({ dialogType, data }) {
  const Component = DialogRegistry[dialogType];
  return (
    <Suspense fallback={<TransitionAnimation />}>
      <Component data={data} onTransition={handleTransition} />
    </Suspense>
  );
}
```

#### 데이터 모델 (Supabase)

```sql
-- 대화 유형별 결과 저장
CREATE TABLE dialog_results (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  session_id UUID NOT NULL REFERENCES sessions(id),
  agent_id UUID NOT NULL REFERENCES agents(id),
  user_id UUID NOT NULL REFERENCES users(id),
  
  -- 판별 정보
  dialog_type TEXT NOT NULL CHECK (dialog_type IN (
    'information', 'data', 'file', 'task', 'multi_agent'
  )),
  detection_method TEXT NOT NULL CHECK (detection_method IN (
    'pattern', 'llm', 'user_explicit', 'hybrid'
  )),
  detection_confidence FLOAT,
  
  -- 컴포넌트 스택 위치
  stack_position INTEGER NOT NULL DEFAULT 0,
  source_result_id UUID REFERENCES dialog_results(id),  -- 전환 전 컴포넌트
  
  -- 결과 데이터 (유형별 JSONB)
  result_data JSONB NOT NULL,
  
  -- 상태
  status TEXT DEFAULT 'active',  -- active, archived, pinned
  created_at TIMESTAMPTZ DEFAULT now(),
  updated_at TIMESTAMPTZ DEFAULT now()
);

-- 인덱스: 세션별 최근 결과 조회
CREATE INDEX idx_dialog_results_session 
  ON dialog_results(session_id, created_at DESC);

-- 인덱스: 컴포넌트 스택 복원용
CREATE INDEX idx_dialog_results_stack
  ON dialog_results(session_id, stack_position);
```

### 6.4 확장성 설계

#### 신규 컴포넌트 추가 프로토콜

스킬 마켓(백서 1.3절)을 통해 새로운 다이얼로그 컴포넌트를 추가할 수 있는 구조:

```yaml
# 다이얼로그 컴포넌트 매니페스트 (dialog-component.yaml)
name: calendar-view
version: 1.0.0
type: custom
trigger:
  keywords: ["일정", "캘린더", "스케줄", "약속"]
  patterns:
    - "\\d+월 \\d+일.*(?:일정|약속)"
ui:
  component: CalendarView
  layout: fullscreen
  transitions:
    from: [information, task]
    to: [information, task, data]
backend:
  handler: calendar-handler
  model: gpt-4o-mini
capabilities:
  - read_calendar
  - create_event
  - set_reminder
```

스킬 마켓에 등록 → 보안 검사(백서 4.1-8항) → 승인 → 클라이언트에 동적 로드.
