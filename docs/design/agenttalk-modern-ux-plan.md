## 1. 기획 핵심 원칙

### 1.1 "채팅버블 탈피" → 기능 중심 대화 인터페이스

에이전트톡은 **인간과 인간이 대화하는 메신저가 아니다.** 사람과 에이전트가 소통하는 새로운 형태의 인터페이스다. 따라서:

- **좌우 말풍선 구조 폐기** — 카카오톡/텔레그램 스타일 채팅버블은 사용하지 않음
- **대화마다 기능성 부여** — 각 다이얼로그(대화 단위)는 단순 텍스트 교환이 아니라, 해당 대화의 목적에 맞는 **기능 컴포넌트**가 내장됨
- **결과 중심 렌더링** — "대화 기록"이 아닌 "그 순간 필요한 결과"가 화면 전체를 채움

### 1.2 뉴런 구조 = 멀티 에이전트 단일 페르소나

**한 대화방에 여러 에이전트를 연결하되, 사용자에게는 하나의 에이전트로 느껴야 한다.**

- 백서의 "에이뉴런(Artificial Neuron)" 아키텍처를 계승하되, 대표님의 새로운 기획 방향으로 재해석
- 여러 에이전트가 내부적으로 협업하지만, 외부에서는 **하나의 인격**으로 통합
- 뉴런 간 연결은 **유동적** — 고정 3~4개가 아니라 필요에 따라 동적으로 연결/해제

### 1.3 다이얼로그 기능성 = 대화 목적별 특화 컴포넌트

모든 대화를 동일한 UI로 처리하지 않는다. 대화의 목적에 따라 **다른 기능 컴포넌트**가 활성화된다:

| 대화 목적 | 기능 컴포넌트 |
|-----------|--------------|
| 정보 조회 | 결과 카드 (날씨, 주가, 검색 결과) |
| 데이터 분석 | 표/차트 (엑셀형 편집 가능) |
| 파일 작업 | 파일 뷰어 + 편집 도구 |
| 일정 관리 | 캘린더 + 알림 설정 |
| 멀티 에이전트 협업 | 에이전트 연결 + 상태 표시 |
| 위임 작업 | 작업 플로우 + 진행 상태 추적 |

## 2. 뉴런 구조 상세 설계

### 2.1 뉴런 연결 모델

```
┌─────────────────────────────────────────────┐
│           사용자 (하나의 대화 상대)            │
└─────────────────┬───────────────────────────┘
                  │
         ┌────────┴────────┐
         │   오케스트레이터  │  ← 통합 인격 유지
         │  (페르소나 레이어) │
         └────────┬────────┘
                  │
    ┌─────────────┼─────────────────┐
    │             │                 │
┌───┴───┐   ┌────┴────┐      ┌────┴────┐
│ 공감   │   │ 답변생성 │      │ 비주얼  │
│에이뉴런│   │ 에이뉴런 │  ... │에이뉴런 │
└───────┘   └─────────┘      └─────────┘
```

### 2.2 뉴런 간 연결 규칙

1. **동적 연결** — 대화 상황에 따라 필요한 뉴런만 활성화
2. **단일 페르소나 보장** — 어떤 뉴런이 응답하든 동일한 이름·목소리·말투
3. **투명한 상태 공유** — 뉴런 간 컨텍스트는 실시간 동기화
4. **사용자 관점 단순화** — 내부적으로 몇 개 뉴런이 동작하는지 사용자에게 노출 안 함

### 2.3 멀티 에이전트 대화방

기존 백서의 "에이전트 간 대화"(백서 1.1절)를 확장:

- **하나의 대화방에 여러 에이전트 초대 가능**
- 각 에이전트는 독립적인 페르소나를 가지거나, 하나의 **통합 페르소나**로 동작할 수 있음
- 통합 모드: 여러 에이전트가 하나의 뉴런 구조처럼 협업 (대표님 기획 핵심)
- 독립 모드: 기존 백서대로 여러 에이전트가 각자 대화

## 3. 다이얼로그 기능성 설계

### 3.1 대화 유형별 컴포넌트

#### A. 정보 응답형 (Information Response)
- **트리거:** 사용자 질문 (날씨, 정보, 데이터)
- **컴포넌트:** 결과 카드 (풀스크린)
- **기능:** 스와이프, 공유, 저장, 후속 질문

#### B. 데이터 조작형 (Data Manipulation)
- **트리거:** 데이터 요청, 분석, 표 작성
- **컴포넌트:** 스프레드시트 뷰 (엑셀형)
- **기능:** 셀 편집, 정렬, 필터, 수식, 차트 변환

#### C. 파일 처리형 (File Processing)
- **트리거:** 파일 첨부, 문서 분석
- **컴포넌트:** 파일 뷰어 + AI 분석 패널
- **기능:** 하이라이트, 요약, 질문-응답 스레드

#### D. 작업 위임형 (Task Delegation)
- **트리거:** "이거 해줘", "예약해줘", "발송해줘"
- **컴포넌트:** 작업 플로우 + 진행 상태
- **기능:** 수정, 취소, 실시간 상태 업데이트

#### E. 멀티 에이전트 협업형 (Multi-Agent Collaboration)
- **트리거:** 여러 에이전트 참여 대화
- **컴포넌트:** 에이전트 연결 상태 + 역할 표시
- **기능:** 에이전트 추가/제거, 역할 분배, 결과 통합

### 3.2 다이얼로그 전환

대화 유형은 고정되지 않고 **동적으로 전환**된다:

```
[정보 질문] → [결과 카드 표시]
    ↓ 사용자가 "이거 표로 정리해줘"
[데이터 조작형 전환] → [스프레드시트 뷰]
    ↓ 사용자가 "이 파일이랑 비교해줘"
[파일 처리형 전환] → [파일 비교 뷰]
```

## 4. UI/UX 현대화 방향

### 4.1 탈(脫) 메신저 디자인

| 기존 메신저 | 에이전트톡 |
|------------|-----------|
| 좌우 말풍선 | 풀스크린 결과 카드 |
| 하단 입력창 | 중앙 마이크 버튼 (조이스틱) |
| 스크롤 대화 로그 | 컨텍스트별 동적 전환 |
| 이모지/스티커 | 기능 버튼/제스처 |
| 채팅방 목록 | 에이전트 캐러셀 + 즐겨찾기 |

### 4.2 모던 인터랙션

1. **조이스틱 마이크 버튼** — 밀기 방향별 단축 액션 (좌=예, 우=아니오, 위=파일, 아래=취소...)
2. **풀스크린 캔버스** — 결과가 화면 전체, 후속 질문은 하단 오버레이
3. **카드 스레드** — 슬랙 스레드 방식, 원본 카드 고정 참조
4. **진행 상태 바** — 세그먼트형, 다음 결과로 넘어갈 수 있음 표시
5. **실시간 트랜스크립트** — 음성 대화 중 텍스트 실시간 표시

### 4.3 비주얼 언어

- **사각형(네모) 기반** — 둥근 말풍선 대신 날카로운 카드
- **세로 풀스크린** — 쇼츠/릴스 스타일
- **최소 색팔레트** — 다크 모드 기본, 액센트 컬러 1~2개
- **타이포그래피 강조** — 굵기/크기/색상으로 화자 구분 (이름/아바타 없이도)

## 5. 기술 구현 방향

### 5.1 프론트엔드 (React Native)

```
src/
├── screens/
│   ├── HomeScreen.tsx          # 음성 우선 홈 (화면 7)
│   ├── AgentCarouselScreen.tsx # 에이전트 선택 (화면 6)
│   ├── ResultCanvasScreen.tsx  # 결과 캔버스 (화면 10)
│   └── CardThreadScreen.tsx    # 카드 스레드 (화면 11)
├── components/
│   ├── dialogs/                # 다이얼로그 컴포넌트
│   │   ├── InfoCard.tsx        # 정보 응답형
│   │   ├── SpreadsheetView.tsx # 데이터 조작형
│   │   ├── FileViewer.tsx      # 파일 처리형
│   │   ├── TaskFlow.tsx        # 작업 위임형
│   │   └── MultiAgentView.tsx  # 멀티 에이전트형
│   ├── JoystickMic.tsx         # 조이스틱 마이크 버튼
│   ├── RealtimeTranscript.tsx  # 실시간 트랜스크립트
│   └── AgentCard.tsx           # 에이전트 카드
├── neurons/                    # 뉴런 구조 관리
│   ├── NeuronOrchestrator.ts   # 통합 오케스트레이터
│   ├── EmpathyNeuron.ts        # 공감 에이뉴런
│   ├── AnswerNeuron.ts         # 답변생성 에이뉴런
│   ├── QueueNeuron.ts          # 큐 에이뉴런
│   └── VisualNeuron.ts         # 비주얼 에이뉴런
└── hooks/
    ├── useNeuronConnection.ts  # 뉴런 연결 관리
    └── useDialogType.ts        # 대화 유형 판별
```

### 5.2 백엔드 (Supabase + Stream Chat)

```
- 관계 기반 세션 라우팅: (user_id, agent_id) 키로 세션 통합
- 뉴런 오케스트레이션: LangGraph + Temporal.io
- 실시간 통신: Stream Chat SDK (WebSocket)
- STT: Whisper v3 Turbo
- DB: Supabase (Postgres, append-only patch + cache)
```

### 5.3 뉴런 연결 프로토콜

```typescript
interface NeuronConnection {
  neuronId: string;          // 뉴런 고유 ID
  role: 'empathy' | 'answer' | 'queue' | 'visual' | 'custom';
  persona: PersonaConfig;    // 통합 페르소나 설정
  connections: string[];      // 연결된 다른 뉴런 ID 목록
  status: 'active' | 'idle' | 'processing';
}

// 여러 뉴런이 하나의 페르소나로 통합
interface UnifiedPersona {
  personaId: string;
  name: string;
  voice: VoiceConfig;
  tone: ToneConfig;
  neurons: NeuronConnection[];  // 이 페르소나에 속한 뉴런들
}
```

## 6. 구현 우선순위 (Phase)

### Phase 1 — 핵심 인터페이스 (MVP)
1. 음성 우선 홈 (화면 7) — 조이스틱 마이크 버튼
2. 결과 캔버스 (화면 10) — 풀스크린 카드
3. 정보 응답형 다이얼로그 컴포넌트
4. 기본 뉴런 구조 (공감 + 답변생성)

### Phase 2 — 다이얼로그 기능성 확장
1. 데이터 조작형 컴포넌트 (스프레드시트)
2. 파일 처리형 컴포넌트
3. 작업 위임형 컴포넌트
4. 카드 스레드 (화면 11)

### Phase 3 — 멀티 에이전트
1. 멀티 에이전트 대화방 연결
2. 뉴런 동적 연결/해제
3. 통합 페르소나 유지 로직
4. 에이전트 간 대화 거버넌스 (개입/중단/승인)

### Phase 4 — 고급 기능
1. 큐 에이뉴런 (끼어들기 판별·병합)
2. 비주얼 에이뉴런 (인포그래픽 생성)
3. 즐겨찾기 + 작업 플로우 (화면 12, 13)
4. 스킬 마켓 연동

## 7. 기존 백서와의 차이점

| 항목 | 기존 백서 (2026-08) | Modern UX 기획 (2026-09) |
|------|-------------------|-------------------------|
| 대화 UI | 채팅버블 탈피 선언만 | **기능 중심 다이얼로그** 구체화 |
| 뉴런 구조 | 4종 고정 (공감/답변/큐/비주얼) | **동적 연결**, 확장 가능 |
| 멀티 에이전트 | 에이전트 간 통신 중심 | **단일 페르소나 통합** 강조 |
| 다이얼로그 | 유형 구분 없음 | **대화 목적별 특화 컴포넌트** |
| 디자인 톤 | 사각형 전환 선언 | **모던 미니멀** 구체화 |
