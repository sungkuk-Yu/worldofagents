## 1. 개인정보 / 데이터 — 🔴 (최우선)

### 1.1 사실관계 (코드 실측)

현재 코드에서 처리되는 개인정보:

| 데이터 | 위치 | 비고 |
|---|---|---|
| 이메일·비밀번호(해시) | Supabase `auth.users` | 회원가입 LoginScreen.tsx — **약관 동의 체크박스 없음, 동의 기록 저장 없음** |
| display_name, phone, timezone, language, preferences, profile(MBTI·관심사) | `users` 테이블 (001_initial_schema.sql:16) | profile JSONB에 MBTI 등 — 목적·항목 최소화 검토 필요 |

| 음성(PCM 스트림) | WS 핸들러 메모리 버퍼 → OpenAI Whisper API 전송 (`stt.ts` transcribeAudio) | 서버 디스크에 오디오 파일 영구 저장은 미확인(메모리 처리 후 파기) — 그 자체는 최소화 원칙에 부합. 단 **Whisper API 전송 = 국외이전** |
| 대화 내용 전체 | chatLlm 프롬프트로 **Alibaba DashScope(qwen3-max, dashscope-intl)** 전송 (config.ts) | 국외이전. 국제판 엔드포인트의 실제 처리 리전(싱가포르 추정 [추측]) 확인 필요 |
| 사용자 DB 전체 | Supabase 호스팅 (리전 미확인) | Supabase 자체도 국외이전 대상(프로젝트 리전이 한국(ap-northeast-2)이 아닌 경우) |

부재가 확인된 것:
- 이용약관/개인정보처리방침 문서·링크·동의 UI: **0건** (앱 전체 검색)
- 회원탈퇴 API·데이터 파기 절차: **없음** (`withdraw`/`deleteAccount` 검색 0건; 세션 삭제 CASCADE만 존재)
- 보유기간·파기 고지: 없음
- 만 14세 미만 연령 확인: 없음
- Codex 리뷰가 지적한 보안 결함(WS 세션 소유권 검사 부재, RLS 누락, dev 인증 자동 전환, 공개 기본값 JWT secret) — 002_rls_hardening.sql로 RLS는 부분 보강됐으나 **WS 소유권 검사·설정 하드닝은 미커밋 상태**

### 1.2 법적 평가

- **법적 근거·동의 (개인정보 보호법 제15조 제1항, 제22조):** 서비스 제공 목적의 수집·이용은 계약 체결·이행(제15조 제1항 제4호)으로 동의 없이도 가능하나, 그 경우에도 **제30조에 따른 개인정보 처리방침 공개**와 수집 시 고지(제20조)는 필수다. 현재는 둘 다 없다.
- **별도 동의 대상:** ① 마케팅 활용(선택) ② 만 14세 미만 아동(제22조의6 — 법정대리인 동의 + 연령 확인 절차 필요) ③ 음성 데이터가 생체인식정보(성문 등)로 활용되면 민감정보(제23조) — 현재 STT는 전사(轉寫) 목적이라 생체인식정보에 해당하지 않는다고 볼 여지가 크지만[추측], 녹음 사실 자체에 대한 명확한 고지는 필요.
- **국외이전 (제28조의8):** OpenAI(Whisper), 알리바바(DashScope), Supabase(리전 확인 필요)로의 이전은 모두 국외이전. 이전받는 자·국가·항목·목적·보유기간·거부 방법/효과를 알리고 **동의를 받거나**, 표준계약 체결·보호위 인증 등 제28조의8 제2~6호의 대체 수단을 갖춰야 한다. AI 챗 서비스의 구조상 대화가 통째로 해외 LLM API로 나가므로 이 항목이 실질상 최대 컴플라이언스 부담이다. 실무상 가장 빠른 길은 처리방침+별도 동의 고지(제1호)와 위탁 구조(제28조의2·시행령)의 병행 설계. [근거: 제28조의8 조문(국가법령정보센터, 시행 2026.9.11. 법률 제21445호) 확인]
- **보유·파기 (제21조):** 목적 달성 후 지체 없이 파기가 원칙. 백서 §4.5의 "원본 영구 보존" 설계는 **그대로 두면 위반 소지** — 보존 필요성(기억 기능)과 파기 의무의 조율을 위해 ① 이용자 탈퇴 시 일괄 파기(현재 API 없음) ② 보존 기간 상한 + 자동 압축·익명화 정책 ③ 처리방침에 보유기간 명시, 세 가지가 필요하다.
- **목적 외 이용 (제18조):** 백서 §1.2 "집단지성으로 개선"(사용자 대화로 서비스 학습)은 수집 목적(대화 서비스 제공)을 초과하는 이용이 될 수 있다. 대화 데이터 학습·개선 사용 여부를 처리방침에 밝히고, 사용한다면 별도 동의 또는 가명처리(제28조의2) 경로를 설계해야 한다. [근거: 아주경제 2026 보도에서 개인정보위가 대화 내용의 AI 학습 활용을 제18조 쟁점으로 지목한 것 확인]
- **안전조치 (제29조) + Codex 보안 결함의 법적 의미:** WS 세션 소유권 검사 부재(타인 세션 열람·주입 가능), 공개 기본값 JWT secret, dev 인증 자동 전환은 유출 사고 시 제29조 위반 → **과징금(제64조의2: 관련 매출액의 3% 이하)** + 손해배상(제39조, 고의·과실 유출은 제39조의4에 따라 최대 5배 징벌 배상)으로 직결된다. "베타라서"가 통하지 않는다 — 외부 사용자가 1명이라도 접속하면 개인정보처리자 의무가 발생한다. **외부 배포 전 Codex 지적의 치명 1~3번 해소가 법적 전제조건.**

### 1.3 MVP에 지금 반영할 것

1. **가입 화면(LoginScreen)에 동의 게이트:** [필수] 이용약관 / [필수] 개인정보처리방침 / [필수] 음성 녹음·전사 처리 고지 / [필수] 국외이전(OpenAI·Alibaba·Supabase — 항목·국가·목적·보유기간·거부 시 효과) / [선택] 마케팅 — 체크박스와 동의 시점·버전 기록 테이블(예: `consents`) 저장.
2. **만 14세 이상 확인 체크** (본인인증은 MVP 범위에서 체크박스+생년 선택 수준으로 가능, 단 아동 대상 마케팅은 금지).
3. **개인정보처리방침 초안 게시**(웹 1페이지 + 앱 내 링크): 처리 항목, 목적, 보유기간, 파기 절차, 국외이전 목록, 이용자 권리(열람·정정·삭제·처리정지), 책임자 연락처.
4. **회원탈퇴 API** (`DELETE /api/me` — auth.users + cascade로 전 테이블 파기) + 처리방침에 "탈퇴 시 즉시 파기" 명시.
5. raw_transcripts 보존 정책: 기본 보존 기간 상한(예: 회원 탈퇴 또는 N개월)을 코드 정책으로 결정 — 무기한은 불가.

### 1.4 출시 전까지

- Supabase 프로젝트 리전 확인 및 한국 리전(ap-northeast-2) 이전 또는 처리방침 반영; DashScope 리전 확인.
- OpenAI·Alibaba와의 관계 법적 정리: 각 사의 API 약관상 데이터 처리 조항(DPA) 검토 — "위탁" 구성이면 제26조 요건(계약서, 처리 목적 제한, 감독) 문서화.
- 개인정보 영향평가(PIA) 수준의 자체 점검표 1회 작성.
- 유출 대응 절차(72시간 내 보호위 신고 — 제34조) 문서화.

## 2. 구독 결제 모델 (앱스토어 인앱결제 우회 — 웹 리다이렉트) — 🟡

### 2.1 사실관계

백서 §5.2·화면 4: 구독 결제는 앱 밖 웹 브라우저에서 처리, 앱은 구독 상태 확인 창구만 담당, 화면에 "외부링크 아이콘 + 웹에서 진행돼요" 안내를 필수 표시. 스킬 마켓 개별 구매는 인앱결제 수수료 반영.

### 2.2 법적 평가

- **한국 전기통신사업법(인앱결제 강제 금지법, 제50조 제1항 제9호):** 이 조항은 **앱마켓 사업자**가 개발사에 특정 결제방식을 강제하는 것을 금지하는 것이지, 개발사의 웹 결제 자체를 규제하지 않는다. 즉 넷플릭스식 웹 리다이렉트는 **한국법상 위법이 아니다.** 오히려 이 법과 방통위 집행(구글 475억·애플 205억 과징금 부과 추진, 2023 통보 — 위원회 구성 문제로 집행 지연 중)이 우리 편이다. [근거: BKL Legal Update 2021, 방통위 발표 보도 확인]
- **실질 리스크는 애플/구글의 개발자 약관(사적 계약):**
  - 애플 리뷰 가이드라인 3.1.1은 앱 안에서 디지털 재화·서비스 구매를 외부 결제 수단으로 유도하는 버튼/링크를 원칙적으로 금지해 왔다. 예외: ① "리더 앱"(3.1.3(a) — 외부에서 구매한 콘텐츠 소비형) ② 미국의 External Purchase Link entitlement(Epic v. Apple 반독점 금지명령 이후).
  - **미국:** Epic v. Apple 항소심(제9연방항소법원 2025-12-11, No. 25-2935)이 애플의 27% 링크아웃 수수료는 금지명령 위반(금지와 다름없는 효과)임을 확인하고 contempt 판정을 유지했다(단, 0% 강제 제재 부분은 과도하다고 파기환송 — 수수료 최종 구조는 유동적). 미국 빌드에서는 외부 링크 허용 방향이 확정적. [근거: 판결문 원문 확인]
  - **한국:** 애플은 한국 앱에 제3자 결제(인앱 내 PG) entitlement만 26%로 허용해 왔고, 앱 내 "아웃링크"는 미국과 달리 명시 허용이 아니다. 화면 4의 "외부링크 아이콘"을 한국 iOS 빌드에 그대로 넣으면 **리뷰 거절·앱 삭제 리스크**. [추측 — 애플 한국 정책은 수시로 변경되므로 제출 시점의 App Store Review Guidelines + 애플 한국 공지 확인 필수]
  - **구글 플레이:** 디지털 콘텐츠는 Play Billing 원칙이나, 외부 결제/링크 정책이 미국(법원 명령)·EU(DMA)·한국에서 완화 흐름. 웹에서 가입한 구독을 앱에서 소비하는 것은 가능하나, 앱 안에서 웹 결제를 적극적으로 유도하는 UI는 심사 리스크.
- **제재 수준(위반 시):** 법 위반이 아니라 약관 위반이므로 → 앱 등록 거부, 기존 앱 삭제, 반복/고의 시 개발자 계정 정지(=전체 앱 사업 중단). 과징금·형사책임 없음. 넷플릭스·스포티파이는 "앱 내 구매 UI 아예 없음 + 가입은 웹에서만"으로 이 구조를 합법적으로 운영하고 있다.

### 2.3 MVP에 지금 반영할 것

- 구독 화면(화면 4)의 외부링크 노출을 **플랫폼·국가별 플래그로 분기** 가능하게 설계(한국 iOS에서는 링크 버튼 대신 "구독은 myagenttalk 웹에서 가입하세요" 수준의 텍스트 안내 또는 아예 숨김). 지금 구조를 만들지 않으면 출시 직전 심사 대응이 급해진다.

### 2.4 출시 전까지

- 제출 시점의 애플/구글 최신 정책(한국·미국·출시국별) 확인 후 빌드 전략 확정.
- 웹 결제 자체는 PG사(토스페이먼츠 등) 표준 약관 + 전자상거래법(청약철회 제17조, 구독 해지·환불 정책 명시) 준수 — 구독 상품은 계속거래이므로 중도해지·환불 기준을 이용약관에 반드시 규정(전자상거래법 제13조 거래조건 표시 포함).

## 3. 토큰 리워드 자동 차감 (백서 §5.1) — 🟢

### 3.1 법적 평가

- **전자금융거래법상 선불전자지급수단 해당 여부(제2조 제14호, 제28조 제2항 선불업 등록):** 토큰이 ① 무상 부여(스킬 사용량 리워드) ② 양도·환불 불가 ③ 당사 서비스(구독료 차감)에만 사용 ④ 현금 인출 불가라면, 선불전자지급수단 등록 대상이 아니라고 볼 여지가 크다. 금융위 법령해석도 무상 제공 포인트·당사 전용·양도 불가 구조에는 등록을 요구하지 않는 방향으로 해석돼 왔다(금융위 유권해석 사례 존재). [근거: 금융위 법령해석(casenote ab8ed0d828) 확인 — 단 개별 사실관계에 따라 달라지므로 **추측 요소 있음**. 실제 발행 시점에 금감원 사전상담 또는 법무법인 확인 1회 권고]
- **주의선(넘으면 규제로 전환):** 토큰을 ① 현금으로 환급 ② 제3자에게 양도·선물 ③ 당사 외 가맹점에서 사용 가능하게 하는 순간 선불전자지급수단/결제업 규제가 트리거될 수 있다. 백서가 "차감 상한, 초과 시 처리는 추후 설계"로 열어둔 부분은 **이 선을 넘지 않는 방향으로** 확정해야 한다.
- **약관 규제:** 리워드 적립률·소멸 조건 변경 권한을 사업자에게 일방적으로 부여하는 약관 조항은 약관규제법 제6조(신의칙)·제10조 심사를 받으므로, 변경 시 사전 고지·기존 적립분 보호 조건을 약관에 명시.

### 3.2 MVP에 지금 반영할 것

- 없음(MVP에 토큰 리워드 미포함이면 해당 없음). 포함한다면 약관에 "무상 부여·양도 불가·현금화 불가·당사 서비스 전용" 4원칙 명시.

### 3.3 출시 전까지

- 토큰 발행 개시 시점에 전자금융거래법 해당 여부 법률 확인 1회(반나절 자문 수준).

## 4. 에이전트 대리 행위 (전화·문자 대리응대, 거래 확정 승인 게이트 — 백서 §3.3) — 🟡

### 4.1 법적 평가

- **대리법상 효과 귀속:** 에이전트가 사용자를 대신해 제3자와 하는 의사표시는 민법상 사용자의 **자동화 도구(기계적 수단)를 통한 의사표시**로 보아 본인(사용자)에게 귀속된다는 해석이 유력하다(학설·실무 [추측 — AI 에이전트 대리에 관한 명시적 판례는 아직 확인되지 않음]). 전자상거래법 제13조는 자동화된 전자적 거래에서의 의사표시 오류(사용자 지시와 다른 계약을 에이전트가 체결) 시 계약 취소 가능 근거를 제공한다.
- **표현대리(민법 제126조):** 승인 게이트를 우회해 에이전트가 권한 밖 계약을 체결하면 상대방 보호를 위해 본인에게 효과가 귀속될 수 있다 → 게이트 설계(백서 §3.3 "민감·비가역 행위는 승인 필수")는 법적 방어 장치이기도 하다. 중고거래 흥정 자율 처리는 "되돌릴 수 있는 행위"로 제한한다는 백서 기준이 타당.
- **책임 구조:** 에이전트 오작동으로 사용자 손해(잘못된 주문, 기한 도과 등) 발생 시 → 서비스 제공자(당사)의 채무불이행·불법행위(민법 제390조, 제750조) 책임 가능. 이용약관의 면책 조항은 **고의·중과실까지 면책할 수 없고**(약관규제법 제7조), "광고한 성능"(24시간 운영, 대리 응대)이 주의의무 기준이 되므로 과장 광고와 면책 조항은 서로 모순되면 무력화된다.
- **전화 대리응대의 추가 쟁점(출시 전):** 통화 상대방은 AI가 응대한다는 사실을 모른다 → ① 상대방 기만(§10 FTC·SB-1001 참조: 판매·거래 목적의 봇 응대는 고지 의무) ② 통화 녹음 시 통신비밀보호법 제3조·제14조(대화 녹음 — 당사자 녹음은 허용되나 "에이전트=당사자" 인정 여부는 [추측] 미검증) ③ 번호 도용·스팸 규제(정보통신망법 제50조 영리목적 광고성 전송 — 대리 문자 발송이 광고성이면 수신자 동의 필요). **MVP에 전화/문자 대리응대는 구현되지 않았으므로(백서상 유료 플랜 미래 기능) 지금은 약관 골격만, 구현 착수 시점에 별도 심층 검토 필수.**

### 4.2 MVP에 지금 반영할 것 (이용약관 골격)

- "이용자의 지시에 따라 에이전트가 수행한 행위의 효과는 이용자에게 귀속" 조항
- 승인 게이트 정책(민감·비가역 행위는 사전 승인)을 약관+UI 양쪽에 명시
- 에이전트 실행 한계·오류 가능성 고지 + 손해배상 책임 제한(단, 고의·중과실 제외 문구 포함)
- 이용자가 에이전트를 타인 기만(사람인 척)에 사용하는 것 금지 조항 (§10과 연동)

### 4.3 출시 전까지

- **전화·문자 대리응대 기능 착수 전 필수(차단 조건) — 대표님 확정(2026-09-26):** 제3자 상대 첫마디 자동 고지 스크립트("저는 ○○님의 AI 비서입니다") + 거래·판매 유도 맥락에서 고지 미노출 시 액션 차단. 이 두 장치 없이는 전화/문자 기능 출시 금지. 상세는 §5.2 시점별 구분표 참조(SB-1001·AI 기본법 제31조③).
- 전화·문자 대리응대 구현 착수 시: 통화 녹음 정책, 광고성 문자 규제(정보통신망법 제50조) 준수 설계.
- 책임보험(기술배상책임·E&O) 검토.

## 5+10. 법률전문 에이전트 & "가장 사람답게" — 🔴 (통합 검토)

> 대표님 확정 제품 목표: "가장 세팅이 잘된 전문가 에이전트를 판다 — 가장 사람답게." 이 항목이 이번 검토에서 가장 무거운 리스크를 가진다.

### 5.1 변호사법 — 법률전문 에이전트

- **법률사무 독점(변호사법 제3조) + 처벌(제109조 제1항 제1호):** 변호사가 아닌 자가 **금품 등 이익을 받고** 법률상담 등 법률사무를 취급하면 7년 이하 징역 또는 5천만원 이하 벌금. 구독료 = "금품 등 이익"으로 평가될 여지가 크다. 무료면 제109조 구성요건(대가성)을 벗어날 수 있으나, 유료 플랜에 포함되는 순간 대가성 논쟁이 열린다.
- **제112조 제3호(표시·기재만으로도 처벌):** "이익을 얻을 목적으로 **법률 상담이나 그 밖의 법률사무를 취급하는 뜻을 표시 또는 기재**"한 것만으로도 3년 이하 징역 또는 2천만원 이하 벌금. 즉 실제로 법률상담을 하지 않아도, **"변호사급 답변 품질"이라는 표시 자체가 위험**하다. 화면스펙의 "변호사급 답변 품질 목표"는 내부 목표 문서이므로 괜찮지만, 이 표현이 앱 설명·마케팅·온보딩 UI에 그대로 나가면 제112조 제3호 리스크가 현실화된다.
- **최신 판례 — 로폼 사건(대법원 2026-02-12 심리불속행 기각, 2025두35483 확정):** 사전 프로그램된 법률문서 **자동작성**은 법률사무 취급이 아니지만, ① 제휴 변호사의 개별 사건 검토서비스는 위반 소지 ② **"생성형 AI를 활용해 이용자 입력을 바탕으로 법률문서를 작성"하는 것은 단순 자동화를 넘어 법률사무 취급에 해당할 수 있다**고 판시(원심). 생성형 AI 법률 서비스에는 직접적으로 불리한 기준선이다. [근거: 법률신문 보도로 원심 판시 확인]
- **선례 — 로톡(검찰 불기소 2022, 법무부 유권해석):** "플랫폼이 특정 변호사를 알선·중개하지 않는 정보 제공"은 합법. 법무부는 2022년 무료 AI 형량예측 서비스도 대가성이 없어 비변호사 법률사무 취급이 아니라고 봤다. 시사점: **① 변호사 연결·알선을 하지 말고 ② 법률"정보" 제공에 머물면 방어선이 생긴다.**
- **FTC(미국 진출 시):** DoNotPay가 "세계 최초 로봇 변호사", "AI lawyer" 광고로 FTC 제소 → 합의(2024, Operation AI Comply) + 허위 주장 금지·소비자 고지 명령. 미국에서 "AI lawyer"류 표현은 집행 선례가 확립된 위험 문구다. [근거: FTC 발표자료 확인]
- **회계관리 에이전트도 동일 논리:** 공인회계사법 제7조(비회계사의 회계업무 취급 금지) + "CPA급" 표현 리스크. 세무사법상 세무대리(세무조정 등) 역시 면허 업무.

**안전 설계(권고):**
1. 포지셔닝을 "법률 **정보 검색·개념 설명·문서 초안 보조**"로 고정. "법률 상담", "변호사", "조언(advice)" 단어 금지.
2. 응답 첫머리/끝 고정 디스클레이머: "AI가 생성한 일반 정보이며 법률 자문이 아닙니다. 구체적 사안은 변호사와 상담하세요."
3. 개별 사건에 대한 결론 제시("승소 가능성", "이렇게 하면 이긴다") 기능 금지 — 로폼 판시의 "개별적 사실관계 검토" 영역이기 때문.
4. 변호사 연결·수임 중개 기능 절대 금지(로톡 선례의 합법 영역 밖으로 나가지 않기).

### 5.2 AI 고지(disclosure) 의무 — "가장 사람답게"와의 정면 충돌 지점

**결론부터: 사람 같은 이름·프로필·말투 자체가 위법은 아니다. 단, "AI라는 사실의 명확한 고지"가 전제 조건이며, 이 고지 의무는 한국·EU에서 이미 발효 중이다.**

| 법역 | 근거 | 내용 | 상태 |
|---|---|---|---|
| 한국 | AI 기본법 제31조 (법률 제21311호) | ① 생성형 AI 기반 서비스는 **AI에 기반해 운용된다는 사실 사전 고지**(계약서·약관·서비스 화면) ② 생성형 AI **결과물 표시**(비가시적 워터마크/메타데이터 허용) ③ **실제와 구분하기 어려운 가상 음향**(= 우리 TTS 음성이 전형적 해당)은 이용자가 명확히 인식할 수 있게 고지·표시 | **2026-01-22 시행 중.** 과태료(사전고지 위반 3천만원 이하)·사실조사는 계도기간(최소 1년, 집행 2027 중반 예상)이지만 **의무 자체는 현재 유효** [근거: 과기정통부 발표·국가법령정보센터 조문 확인] |
| 미국 연방 | FTC법 §5 (기만적 관행) | AI임을 숨기고 사람인 척하여 거래를 유도하면 기만. DoNotPay 합의가 선례. FTC는 2025-09 소비자향 AI 컴패니언 챗봇 7개사(OpenAI·Meta·Character.AI 등)에 6(b) 조사명령 — "사람다운 컴패니언" 카테고리 전반이 감시 대상에 들어감 [근거: FTC 보도자료 확인] | 집행 활발 |
| 캘리포니아 | SB-1001(BOT Act, 2019 시행) | 봇을 이용해 **판매 유도·투표 영향** 목적으로 사람과 온라인 소통하면서 봇임을 공개하지 않으면 위법. 위반당 $2,500 이하 민사제재(AG·검사 집행, 사인 소권 없음). 예외: 사람이 obviously 알 수 있는 경우 등 | 시행 중. 우리 에이전트가 제3자(판매 상대방 등)와 대화하는 기능(대리 협상) 출시 시 직접 적용 |

(2) 합성 음향·텍스트 산출물은 기계판독 가능 표시. 위반 시 €15M/글로벌 매출 3% 이하 과태료 | **2026-08-02부터 적용 개시** (Digital Omnibus로 고위험 규제만 연기됐고 제50조는 연기 안 됨). 초기 목표 시장(한·미·일·중·영·동남아)에는 EU가 없어 **현시점 직접 적용 아님** — EU 진출 시 즉시 발동 [근거: AI Act 조문·집행 일정 복수 소스 확인] |

**"가장 사람답게"의 법적 경계 (판단):**
- 허용: 사람 같은 이름(예: "수아"), 페르소나, 자연스러운 말투, 공감 표현 — **AI임이 고지된 상태에서는** 문제 없음. AI 기본법도 EU AI Act도 "사람처럼 만들지 마라"가 아니라 "AI임을 알려라"다.
- 금지·위험: ① "사람과 구분 불가능" "튜링테스트 통과"류 마케팅(기만 광고) ② 이용자가 제3자에게 에이전트를 사람으로 속여 쓰게 방치(약관으로 금지 필요 — 캘리포니아 SB-1001은 봇을 '사용하는 자'를 규율하므로 이용자 행위이지만, 플랫폼 방조 리스크) ③ 제3자와의 전화·거래 소통에서 AI 신분 미공개 ④ 고지를 약관 속에 파묻기(AI 기본법 시행령상 "계약서·약관·서비스 화면" 모두 가능하나, EU는 화면 고지를 요구 — 처음부터 화면 고지로 통일하는 것이 안전).

**⚖️ 대표님 확정 방향 (2026-09-26, 김비서 경유) + 법적 평가:**

> 대표님 확정: ① 마케팅/브랜드 문구로 "사람다운 에이전트"는 **유지** — "에이전트" 용어 자체가 AI를 드러내므로 기만이 아니다 ② 고지 의무는 **대화 순간 + 제3자 접촉**에 적용 — 특히 백서 §3.3 전화·문자 대리응대에서 상대방(제3자)에게 **"AI 비서입니다" 고지를 선행하는 기능** 필요(SB-1001 대응) ③ MVP(텍스트 채팅)는 제3자 접촉 기능이 없어 급하지 않음 — 단, **전화/문자 기능 착수 전 필수 해결 항목**으로 명시.

법률 검토 관점 평가:
- **①에 대한 의견 — 타당, 단 한 가지 유보.** "에이전트(agent)"라는 용어는 2026년 현재 AI 제품 범주로 통용되므로 "사람다운 에이전트" 문구 자체는 기만적이라고 보기 어렵다. FTC §5나 표시광고법도 "문구가 합리적 소비자를 오인시키는가"가 기준인데, "에이전트"가 포함된 한 오인 소지는 낮다. **유보:** 같은 캠페인 안에서 "사람과 구분 불가", "진짜 사람 같은데 사람 아님(속이는 취지)" 등 구분 불가능성을 **卖点으로 내세우는 변형 문구**는 여전히 금지 리스트(§5.3)로 관리할 것. "사람다운"은 톤, "구분 불가능"은 기만 주장 — 이 선은 유지한다.
- **②에 대한 의견 — 정확하며, 제3자 접촉이 SB-1001의 핵심 적용 지점이다.** SB-1001은 "판매 유도·거래 목적"의 봇 소통에서 봇임을 공개하지 않는 것을 규제하는데, 우리 에이전트가 제3자(판매자·상대방)와 협상·응대하는 순간이 바로 그 요건에 들어온다. "에이전트"라는 단어만으로는 부족하고, 대표님 확정보다 강한 명시 고지 — **"저는 ○○님의 AI 비서입니다"를 통화/문자 첫머리에 자동 삽입** — 가 안전선이다. AI 기본법 제31조 제3항(구분 어려운 가상 음향의 명확한 고지)도 전화 TTS 응대에 직접 적용된다.
- **③에 대한 의견 — 동의. MVP 텍스트 채팅은 상대가 이용자 본인뿐**이므로 제3자 고지 기능은 불요하다(이용자 상대 AI 고지 UI는 §8·아래 구분대로 여전히 필요). 단 "전화/문자 기능 착수 전 필수"를 아래 구분표와 §4.3에 명시했다.

**시점별 구분 정리 (확정 방향 반영):**

| 시점 | 조치 | 근거 |
|---|---|---|
| **MVP(지금, 텍스트 채팅)** | 온보딩 첫 화면/메시지에 "AI 에이전트입니다" 고지 + 응답 카드 "AI 생성" 표기 + 마케팅 문구 금지 리스트 배포. 제3자 고지 기능은 **불요**(제3자 접촉 없음) | AI 기본법 제31조 ①②(시행 중) |
| **출시 전(공개 베타~정식)** | TTS 음성 첫 사용 시 "AI 생성 음성입니다" 고지 1회 + 처리방침 기재, 이용약관에 "이용자가 에이전트를 타인에게 사람으로 속여 사용하는 행위 금지" 조항 | AI 기본법 제31조 ③, FTC §5, 약관규제법 |

### 5.3 "변호사급/CPA급" 광고 문구 — 표시광고법·FTC

- **표시·광고의 공정화에 관한 법률 제3조:** 허위·과장 표시 금지. "변호사급 품질"은 객관적 실증이 사실상 불가능한 등급 주장 → 과장 광고 리스크. 공정위는 AI 서비스의 성능 과장 광고를 전자상거래법·표시광고법으로 점검해 왔다.
- **FTC(미국):** AI 성능 주장에 대한 실증(substantiation) 요구 — DoNotPay 선례.
- **허용 문구 예시(제안):** "법률 문서를 읽기 쉽게 풀어주는 AI" / "계약서 초안 작성을 도와주는 AI" / "회계 용어와 가계 정리를 돕는 AI" + 모든 전문가 영역 화면에 "AI 생성 정보이며 전문가 자문을 대체하지 않습니다" 고정 표기.
- **금지 문구 예시:** "변호사급", "CPA급", "AI 변호사", "소송에서 이기는 방법", "사람보다 정확한 세무 처리".

### 5.4 전문 영역 의존 손해의 책임 구조

- 디스클레이머는 필요조건이지 충분조건이 아님: "변호사급"으로 광고해 놓고 "책임 없음" 약관은 모순 → 약관규제법 제6조(신의칙)상 무효 가능성 + 광고가 주의의무 기준을 올림. **광고 수위를 낮추는 것이 곧 책임 리스크를 낮추는 것.**
- 이용약관 필수 조항: 전문가 서비스 아님 명시, 최종 판단은 이용자 책임, 고의·중과실 제외 책임 제한(12개월 이용료 한도 등), 위기 상황(자살·의료 응급) 시 전문기관 안내 의무화.
- 법률·회계·의료 응답에 대한 가드레일(개별 사건 결론 제시 차단)을 프롬프트·필터 수준에서 구현하고, 그 사실을 약관·안전 페이지에 기재.

### 5.5 MVP에 지금 반영할 것

1. 온보딩/채팅 화면 AI 고지 상시 표기 — 마케팅 문구 "사람다운 에이전트"는 대표님 확정대로 **유지 가능**(§5.2 확정 방향 참조, 단 "구분 불가능" 주장형 변형 문구는 금지)
2. 법률·회계 에이전트 응답에 고정 디스클레이머 삽입 (5.1)
3. 이용약관에 "전문가 서비스 대체 아님 + 책임 제한 + 이용자 오남용(사람으로 속여 사용) 금지" (5.4, §5.2)
4. 마케팅 문구 가이드(금지/허용 리스트 — 본 절 5.3)를 팀 공유 문서로 배포

### 5.6 출시 전까지

- 법률전문 에이전트의 응답 범위(정보 제공 vs 개별 자문 경계)에 대해 **변호사 자문 1회 필수**(§11). 로폼 판시("생성형 AI 법률문서 작성 = 법률사무 해당 소지") 때문에 이 경계는 내부 판단으로 넘길 수준이 아니다.
- FTC 컴패니언 챗봇 조사 동향 모니터링(미국 출시 시 연령 제한·청소년 보호 정책 필요 가능성).

### 9.2 법적 평가

- **"My" 접두만으로 회피되는가 — 상표법상 [추측/요확인]:** 한국 상표 심사실무에서 "My", "The", "i"류의 식별력 없는 접두는 상표의 요부로 보지 않는 경향이 있어, "MyAgentTalk"이 "AgentTalk" 등록상표와 유사(상표법 제34조 제1항 제7호) 판정될 여지가 있다. 현재 "Agent Talk"의 **한국 등록상표 존재 여부가 미확인**이라 확정은 불가 — KIPRIS 확인이 선행되어야 한다. 다만 **앱스토어 이름 자체는 "Agent Talk"와 문자열이 다르므로 등록 충돌 없이 사용 가능**할 가능성이 높다(애플은 앱명 중복만 금지).
- **혼동 리스크(부정경쟁방지법 제2조 제1호 나목 — 출처 혼동):** 독일 "Agent Talk" 앱이 **한국 스토어에서 동일 카테고리(생산성/AI 에이전트)로 서비스 중**이라는 점이 실질 리스크다. 등록상표가 없어도 선사용자에게 나목(주지 표지 혼동)·영업주체 혼동 주장 여지가 있고, 검색 결과 혼동(ASO)은 확실하다. "MyAgentTalk"은 문자상 구별되지만 음성 호칭("마이 에이전트 톡" vs "에이전트 톡")은 유사하다.
- **내부 브랜드 구조 충돌(백서 2026-08-16 명칭 정리와 대조) — 대표님 판단 필요:** 백서상 "마이 에이전트"는 과거 마스코트 브랜드로, **에이전트메이킹 프로그램으로 개명·폐기된 이름**이다. 제품명을 "마이에이전트톡"으로 하면 ① 폐기된 "마이 에이전트" 브랜드 자산과 사용자에게 혼선을 주고(메이킹 프로그램 vs 채팅앱 구분이 "마이"라는 공통 접두로 흐려짐) ② WOA(상위 holding) → 개별 제품 브랜드 구조에서 "마이"가 특정 하위 제품(메이킹 프로그램의 옛 이름)을 지시했던 히스토리와 충돌한다. 법률 문제가 아니라 브랜드 체계 문제지만, **개명 카드(t_1b308848)가 완료되기 전에 대표님께 이 충돌을 올려야 한다.**
- **Synergetics AgentTalk™:** B2B 프로토콜 브랜드로 상품류(소프트웨어/SaaS)가 겹칠 수 있음. 미국 출시 시 USPTO 등록 여부 확인 후 판단 — 미등록이면 선사용(™) 주장만 가능하고 우리 "MyAgentTalk"에 대한 실질 위협은 낮음 [추측].

### 9.3 권고

1. **개명 확정 전 KIPRIS·USPTO 수동 조회 1회**(30분): "에이전트톡", "AgentTalk", "MyAgentTalk", "마이에이전트톡" × 제9류(소프트웨어 앱)·제38류(통신)·제42류(SaaS). — 이 작업은 자동화 실패로 미완이므로 **긴급 후속 조치로 분리**했다(§13).

3. 내부 브랜드 충돌(§9.2 세 번째)은 대표님 재결정 사항으로 김비서 경유 에스컬레이션.
4. 상표 출원은 §7.3의 변리사 상담에 상표 2건(국문·영문)을 묶어 진행 — 베타 오픈 전 완료(선출원주의).
